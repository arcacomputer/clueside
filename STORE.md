## Detailed description (paste into the Store listing)

Clueside estimates whether images on web pages (or files you drop in the popup) were likely created with AI. All inference runs on your device with WebGPU or WASM. Image bytes are not uploaded to a server.

How it works
- Two local neural heads: CommunityForensics DeepfakeDet-ViT (MIT, FP32 ONNX)
  plus a DINOv2-small feature probe (transparent logistic head). Fusion is
  CF-primary: CommunityForensics wins below a 5% rescue floor and at or above
  65%; between 5% and 40% DINO may only lift if it is near-saturated (>= 98%);
  between 40% and 65% DINO may lift at >= 70%. A flat-graphic guard prevents
  DINO from overriding CF on catalog art and UI-like images. CommunityForensics
  TTA uses the maximum raw sigmoid from inspected crops. The decision threshold
  is raw 65% p(AI), with no score remapping.
- Hybrid metadata: C2PA digitalSourceType, EXIF/XMP/IPTC, generator text in PNG/JPEG, and weak URL hints. A URL hint alone cannot push a score over 65%.
- Overlay badges on large page images. Popup drop zone for local files. Works fully offline after install; the zip includes all model weights.

Privacy
- Images never leave your device.
- No analytics, no account, no cloud inference API.
- No runtime downloads: all weights ship in the package (fetched from Hugging Face at build time).

Honesty
- This is a single-purpose AI image detector. It does not block ads, manage tabs, or rewrite pages beyond overlay badges.
- Photoreal DALL-E 3 images can score below 65%. Ordinary camera photos are the priority not to false-flag.
- Public n=19 fixture numbers are a small test set, not a claim about a private benchmark.

## Single purpose

This item only detects likely AI-generated images and shows a local confidence badge. It does not include unrelated features.

## Permission justifications (paste into the permissions form)

### host_permissions / `<all_urls>`

The extension must fetch the same image URLs the page already displays so pixels can be decoded in an offscreen document. Canvas taint and CORS would otherwise block local analysis. Bytes are used only for on-device inference and metadata parse. They are not sent to a backend.

### offscreen

ONNX Runtime needs a document with DOM, canvas, and WebGPU or WASM. Chrome MV3 service workers cannot run that stack. The offscreen document never renders UI to the user.

### storage

Saves the user's raw threshold (default 65%), enable toggle, and auto-scan toggle via `chrome.storage.sync`.

### alarms

Schedules the optional once-daily GitHub release-version check. It does not
send image or browsing data.
